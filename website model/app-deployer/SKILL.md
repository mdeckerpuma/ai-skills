# App Deployer

Takes the HTML/JS project files generated by crud-builder (and optionally form-builder or
dashboard-builder), validates that environment variables are set, writes the Vercel deploy
config, runs the deploy, and returns a live public URL. Saves a deploy record to memory and
a deploy-report.md to the project folder. Never touches credentials — all secrets live in
.env or Vercel environment variables.

---

## Guardrails

- **Never deploy with missing or placeholder .env values.** Before running any deploy
  command, validate that SUPABASE_URL and SUPABASE_ANON_KEY are present and do not contain
  placeholder text (e.g., `your-project.supabase.co`, `your-anon-key-here`). Hard stop if
  either is a placeholder:
  > "Deploy blocked: .env contains placeholder values. Fill in your real Supabase credentials
  > before deploying."
- **Never silently redeploy a project that already has a live URL.** If memory contains a
  deploy record for this project, surface it and require explicit confirmation:
  > "This project was previously deployed to [URL]. Redeploying will overwrite it. Continue? (yes/no)"
- **Never hardcode credentials anywhere.** `vercel.json` must never contain Supabase keys,
  API tokens, or any secret. All secrets are set via `vercel env add` commands or the Vercel
  dashboard — never written to config files.
- **Never proceed if project folder or blueprint.json is missing.** If the project folder
  doesn't exist or contains no HTML files, stop:
  > "No project files found. Run /crud-builder first to generate the app pages."
- **Never run deploy without confirming the target.** Even though Vercel is the only
  supported target, always show the user what is about to be deployed before executing:
  > "Ready to deploy [App Name] to Vercel. Project folder: [path]. Continue? (yes/no)"

---

## Gotchas

- **Vercel CLI not installed or not authenticated.** The most common real-world blocker.
  Before running any `vercel` command, check for the CLI:
  ```
  vercel --version
  ```
  If missing, stop and provide install instructions:
  > "Vercel CLI not found. Install with: `npm install -g vercel`
  > Then authenticate with: `vercel login`"
  If CLI exists but returns auth error, stop:
  > "Vercel CLI is not authenticated. Run `vercel login` and try again."

- **Vercel project not linked.** First deploy to a new project requires `vercel link` or
  an interactive `vercel` prompt. Flag this to the user rather than silently failing:
  > "This looks like a first deploy. Vercel may prompt you to link/create a project —
  > respond to the prompts, then the deploy will continue."

- **Environment variables not set in Vercel.** Writing .env locally does not push env vars
  to Vercel. After deploy, always remind the user to set env vars in Vercel:
  > "IMPORTANT: Your Supabase keys in .env are NOT automatically uploaded to Vercel.
  > Set them via: `vercel env add SUPABASE_URL` and `vercel env add SUPABASE_ANON_KEY`
  > Then redeploy: `vercel --prod`"

- **Static HTML routing on Vercel.** By default, Vercel doesn't handle client-side routing
  for static sites. The generated `vercel.json` must include a rewrite rule to route all
  paths to `index.html`. Omitting this causes 404s on direct URL access.

- **deploy-report.md not updated on redeploy.** If the file already exists, overwrite it
  (append to history section if present, replace URL with the latest). Never leave a
  deploy-report.md with a stale URL.

## Steps

### 0 — Pre-flight

1. Identify the project name/path. Look for:
   - An explicit argument passed to the skill
   - Most recently modified project folder in `C:\Users\mdecker\.claude\skills\website model\projects\`
   - If ambiguous, list available project folders and ask the user to pick one.

2. Verify the project folder exists and contains at minimum `index.html` or a `pages\` folder
   with at least one HTML file. If empty or missing, stop with the message above.

3. Check if `blueprint.json` exists. Read it to get `app.name`, `stack.deploy`, and
   `stack.auth`. If missing, warn but continue — blueprint is informational at this stage.

4. Check memory for an existing deploy record for this project:
   - Key: `deploy_[app-name-kebab]`
   - If found, show the existing URL and require confirmation before proceeding.

5. Load memory: `preferred_deploy_target` (should be `vercel` — if somehow different, flag it).

---

### 1 — Validate environment variables

1. Read `projects\[app-name]\.env` (if it exists).
   If `.env` doesn't exist, check `.env.example`.

2. For each required variable (`SUPABASE_URL`, `SUPABASE_ANON_KEY`), verify:
   - The variable is present in the file
   - The value does not match the placeholder pattern from `.env.example`

3. If any variable is missing or is a placeholder — hard stop. Show exactly which variable
   is the problem and what value it expects.

4. If `.env` doesn't exist at all, ask:
   > "No .env file found. Do you want to create one now? (yes/no)"
   If yes, prompt for each required value and write the file. Never echo keys back to chat
   in full — show only the first 8 characters + `...` as confirmation.

---

### 2 — Write vercel.json

Write `projects\[app-name]\vercel.json`:

```json
{
  "version": 2,
  "builds": [
    { "src": "**/*.html", "use": "@vercel/static" },
    { "src": "**/*.js", "use": "@vercel/static" },
    { "src": "**/*.css", "use": "@vercel/static" }
  ],
  "routes": [
    { "src": "/(.*)", "dest": "/index.html" }
  ]
}
```

This handles static HTML/JS routing and prevents 404s on direct URL access.

If `vercel.json` already exists — check if it matches the above structure. If different,
show the diff and ask: **Overwrite / Keep existing / Cancel**.

---

### 3 — Deploy to Vercel

1. Show a pre-deploy summary and wait for confirmation:
   ```
   DEPLOY SUMMARY — [App Name]
   ────────────────────────────────────
   Project folder: projects\[app-name]\
   Target:         Vercel
   Entry point:    index.html
   ────────────────────────────────────
   Ready to deploy? (yes/no)
   ```

2. Check for Vercel CLI:
   ```
   vercel --version
   ```
   If not found or not authenticated, stop with install/login instructions (see Gotchas).

3. Run the deploy:
   ```
   vercel --prod --yes
   ```
   - `--prod` deploys to the production URL (not a preview URL)
   - `--yes` skips interactive prompts where possible

4. Capture the output and extract the live URL from the deploy response.
   If no URL is found in the output, stop and show the raw output:
   > "Deploy command ran but no URL was captured. Raw output: [output]
   > Check your Vercel dashboard for the live URL."

---

### 4 — Post-deploy: set environment variables

After a successful deploy, remind the user about env var setup in Vercel:

```
IMPORTANT: Set your environment variables in Vercel before the app will work:

  vercel env add SUPABASE_URL
  vercel env add SUPABASE_ANON_KEY

After setting them, redeploy:
  vercel --prod
```

If the user wants, offer to run the `vercel env add` commands interactively now.

---

### 5 — Write deploy-report.md

Write `projects\[app-name]\deploy-report.md`:

```markdown
# Deploy Report — [App Name]

## Latest Deploy
- **URL**: [live URL]
- **Target**: Vercel
- **Deployed at**: [timestamp]
- **Project folder**: projects\[app-name]\

## Files Deployed
[list of pages\*.html files]
[js\*.js files]
[css\*.css files]
index.html
vercel.json

## Environment Variables Required
- SUPABASE_URL
- SUPABASE_ANON_KEY
Status: Set in Vercel dashboard? [ ] Yes / [ ] No

## Deploy History
| Deploy # | URL | Timestamp |
|----------|-----|-----------|
| 1        | [URL] | [timestamp] |
```

If the file already exists, append a new row to the Deploy History table and update the
"Latest Deploy" section with the new URL and timestamp.

---

### 6 — Write memory and confirm

Write a deploy record to memory:
- Key: `deploy_[app-name-kebab]`
- Value:
  ```
  App: [App Name]
  URL: [live URL]
  Target: Vercel
  Deployed: [timestamp]
  Project: projects\[app-name]\
  ```

Also update `preferred_deploy_target` = `vercel` if not already set.

Print final confirmation:

```
DEPLOYED — [App Name]
────────────────────────────────────────────
Live URL:   [URL]
Target:     Vercel
Report:     projects\[app-name]\deploy-report.md
────────────────────────────────────────────
NEXT: Set env vars in Vercel dashboard, then run /app-iterator to make changes, /auth-integrator to add login, or /frontend-design to apply a visual theme to any page.
```

## Memory Allocation

Reads:
- `preferred_deploy_target` — to confirm Vercel is the intended target
- `deploy_[app-name-kebab]` — to check if project was previously deployed

Writes after successful deploy:
- `deploy_[app-name-kebab]` — full deploy record (URL, target, timestamp)
- `preferred_deploy_target` — set/confirm to `vercel`

Project files written:
```
C:\Users\mdecker\.claude\skills\website model\projects\[app-name]\
├── vercel.json          ← Vercel static deploy config
└── deploy-report.md     ← deploy log with URL and history
```

## Versioning & Iteration

- If Azure Static Web Apps support is needed later → add a target-selection step before
  Step 2 and write `staticwebapp.config.json` instead of (or alongside) `vercel.json`.
- If Railway support is needed → add a `railway.json` / `Procfile` write path.
- If env var pushing to Vercel becomes automated (via `vercel env add`) → build it into
  Step 4 as an interactive sub-flow rather than a manual reminder.
- After 3+ real deploys → check if the vercel.json routes block needs adjustment for
  specific page structures (deep paths, API routes, etc.).
